# 项目进度管理系统 —— 需求文档与产品设计方案（v0.1）

> 工作名：proj-timeline，暂定中文名「项目时间线」
> 状态：v1 需求基线 ｜ 交付顺序：本设计文档 → 静态 HTML 原型 → 契约与执行计划评审 → 开发
> 开发契约以本文件的业务规则、`接口设计.md` 的 HTTP 契约和 `database.sql` 的物理表结构为准；`开发文档.md` 只说明实现方式，不能覆盖前三者。

## 1. 背景与目标

**背景**：10 人以内团队，多项目并行。需要一个自托管的进度管理系统，解决三个痛点：

1. 项目的**当前进度**一眼可见（现在靠问、靠开会）；
2. 进度**工作项化**：每个里程碑有明确时间、状态、负责人；
3. **责任明确**：模块谁负责、小功能何时交付、Bug由谁修复，一清二楚。

**目标**：围绕小团队功能交付，管理项目、功能模块、工作项、交付资料、Bug和周报。工作项是最小交付单位；历史任务与工时保留兼容，不作为日常必填层级。

**核心设计原则**（来自 GitHub 调研，详见两份调研报告）：

| 原则 | 说明 | 来源 |
|---|---|---|
| 工作项是独立实体 | 工作项 = 一个小功能 + 计划/实际日期 + 状态 + 负责人 + 交付资料 + 关联Bug | GitHub Milestone、Plane Cycle、禅道里程碑 |
| 负责人双轨 | 负责人（对功能交付负责）+ Bug执行人，默认继承功能负责人、可合法改派 | 禅道"模块默认指派人"、Plane Module.Lead |
| 状态与异常分离 | 状态 = 未开始/进行中/已完成/已取消；"受阻""延期"是**可叠加的异常标记** | 商业产品常见做法（延期=计划 vs 实际偏差） |
| 延期闭环 | 到期自动红/黄预警 → 负责人填原因 → 自动通知 PM | 禅道、Teambition 汇报模式 |

## 2. 调研摘要（结论已合并）

**国际高星产品**（报告：[research/开源项目管理系统调研报告.md](../research/开源项目管理系统调研报告.md)）：
- **Plane**（59.5k⭐，最活跃）：Module（带 Lead 负责人）+ Cycle + Issue 父子 + 甘特依赖，进度自动聚合——"模块+负责人"最直接样板。
- **OpenProject**（15.8k⭐）：一切皆 Work Package，Phase/Milestone 是 Type 之一，角色权限矩阵最强。
- **Taiga**（≈13k⭐）：冲刺时间盒 + Epic→Story→Task 三层，已进入维持期。
- 其余（Focalboard 已停维、Vikunja、Leantime、Huly、Wekan、Kanboard）各有取舍，结论：**工作项独立实体 + 负责人双轨**是主流。

**国产产品**（报告：[pm-systems-research.md](../pm-systems-research.md)）：
- **禅道 ZenTao**：里程碑/阶段/迭代三形态；模块树设**默认指派人**（新任务自动带出）；工时预估/消耗/剩余三值；燃尽图；周报对象化——与我们的目标最接近的参考。
- **ONES / Worktile / Teambition / TAPD**：术语统一为 负责人/处理人+抄送、里程碑挂发布计划、阶段+交付物、工时统计、甘特+报表。
- **结论**：国产开源 PM 主流 PHP，但技术栈不影响产品模型；10 人自托管用 Java + MySQL 完全可行。

## 3. 用户与角色

### 3.1 角色设计（10 人团队，一人可多职）

| 角色 | 类型 | 职责 | 系统内典型操作 |
|---|---|---|---|
| 管理员 | 全局角色 | 管用户账号、系统设置 | 建账号、设全局角色、删数据 |
| 普通用户 | 全局角色 | 干活 | 被分配后操作 |
| 只读观察者（老板/管理层） | 全局角色 | 只看全局，不操作 | 看总览、周报、延期预警 |
| PM（项目经理） | **项目内职务** | 对项目整体结果负责 | 建项目、建模块、建工作项、指定负责人、确认周报 |
| 模块负责人 | **项目内职务** | 对模块负责 | 管理本模块功能交付和Bug，向PM汇报 |
| 工作项负责人 | **项目内职务** | 对工作项负责 | 确认功能交付、管理资料、处理/指派关联Bug |
| 成员（执行人） | **项目内职务** | 具体干活 | 交付本人负责的功能、处理本人Bug、提交资料 |

**关键约定**：全局角色只有三种（管理员/普通用户/只读）；PM、模块负责人、工作项负责人是**项目内的职务**，同一个人在不同项目可以担任不同职务（A 项目的 PM、B 项目的工作项负责人）。

### 3.2 负责人双轨（简化版）

- 每个**模块**有一个**负责人**（模块负责人，由 PM 指定）。
- 每个**工作项**有一个**负责人**，**新建时自动带出所属模块的负责人**，可改派。
- 每个工作项有一位交付负责人；Bug默认指派给关联功能负责人，可由功能管理者改派给本项目有效非VIEWER成员。
- v1 均为单人负责（问责清晰），预留"多负责人/抄送"字段扩展。

## 4. 术语表

| 术语 | 含义 |
|---|---|
| 项目 Project | 一次有明确目标的交付集合，有 PM 和成员 |
| 模块 Module | 项目的功能块划分（如"用户与登录""订单与支付"），有模块负责人 |
| 阶段性目标 Stage Target | 直接属于项目的关键目标，包含目标名称、说明、目标日期，以及可选的量化指标（当前值 / 目标值 / 单位）；与模块无关 |
| 工作项 / 里程碑 Node | 模块下的时间检查点（如"5/10 接口联调完成"），有负责人、状态、计划/实际日期 |
| 任务 Task | 兼容旧记录；通用任务不再是默认层级，kind=BUG行承载独立Bug状态/执行人/记录/附件 |
| 变更申请 Change Request | 成员对**别人负责的模块**提出的名称/描述/负责人修改，由 PM 审批后由系统自动生效 |
| 交付物 Deliverable | 工作项要交出的资料清单项（开发文档、接口文档、测试记录等），状态为待提供/已提供，可选关联工作项文件 |
| 负责人 | 对结果负责的人（模块负责人/工作项负责人/任务执行人） |
| 计划日期 | 工作项/任务原定日期；**实际日期** = 真实发生日期，用于计算延期 |
| 状态 | 工作项的 4 态：未开始 / 进行中 / 已完成 / 已取消 |
| 异常标记 | 叠加在状态上的标记：**受阻**（有阻塞问题）、**延期**（计划晚于实际） |
| 进度 | 功能按是否确认交付计数；模块/项目完成率 = 已交付工作项 ÷ 未取消工作项，资料/Bug/历史任务不参与 |
| 工时 | 计划人天（估的）与按工作日期逐日记录的实际人天（花的），二者对比看偏差 |
| 通知 | 站内通知（延期预警 / 指派 / 完成 / 周报） |
| 周报 | 系统按本周变化自动生成草稿，PM 确认后发布的汇报 |

## 5. 功能需求

### F1 登录与账号
- 管理员创建账号（用户名/姓名/密码/全局角色），账号可停用；停用不删除历史责任、工时和日志。
- USER 登录后进入“我的工作”，按逾期/日期查本人负责的工作项与本人Bug；ADMIN/VIEWER 进入项目总览。我的工作支持项目、状态、关键词与已完成/历史筛选，读取由服务端分页，不逐个项目拼接。
- 验收：普通用户看不到账号管理入口；停用账号无法登录。

### F2 项目管理
- 有效的普通用户或管理员可创建项目：名称、代号、描述、项目开始日期（必填）、项目完成日期（可空）；创建者自动成为 PM。项目不再使用时归档，保留周报和责任历史；PM/管理员可恢复为活跃状态，归档期间项目业务数据只读。
- PM/管理员可在项目内维护多个阶段性目标。目标日期不得早于项目开始日期；项目完成日期存在时不得晚于完成日期。
- 阶段性目标可附一个**可选的量化指标**（指标名称、目标值、当前值、单位），用于回答“这个目标达成了多少”：达成度 = 当前值 ÷ 目标值，四舍五入并夹在 0–100（超额按 100 显示）。四列都不填时保持原来的日期型里程碑；指标只做展示与复盘参考，不评分、不带周期、不与绩效挂钩（v1 明确不做 OKR）。
- 项目概览直接展示功能模块及负责人、交付数，并展示交付目的、PM、项目计划、当前风险及原因、近期阶段目标和本周计划；七项固定导航为概览/模块/工作项/时间线/文档/周报/设置。首次创建项目后可先建立模块，再安排首项交付，成员和阶段目标可稍后完善。
- 项目成员管理：PM 添加/移出成员；新建项目者自动成为该项目 PM，每个项目恰有一个 PM，转交 PM 须先把接任者加入项目。
- 验收：项目卡片展示说明、PM、日期、进度与可点击风险；默认活跃项目，支持归档/全部、搜索和真实分页。受阻风险仅计未关闭工作项。

### F3 模块管理
- 项目下维护模块列表（v1 一层，预留多级）：名称、描述、**模块负责人**。模块用于功能拆分，不承载项目阶段目标。
- 模块有独立列表页；项目概览与顶部“模块”导航均可进入，空模块也显示。模块卡片进入模块工作页，展示该模块的工作项与过程文件；“工作项”页仍按模块分组，并可返回模块列表。
- PM/ADMIN 可增删改模块、指定/变更负责人；模块负责人可直接改本模块名称/说明/负责人，排序、创建和删除仍仅 PM/ADMIN。含工作项的模块不可删除。
- 模块负责人进入自己负责的模块后，可查看工作项列表并填写工作项名称、说明、计划起止日期和负责人；创建后进入功能详情维护交付状态、资料与Bug。
- **变更申请**：没有模块编辑权限的项目成员（非 VIEWER）可对模块的**名称、描述、负责人**提交变更申请，并可选填申请说明；同一模块同时只允许一个待审批申请。项目经理（或管理员）审批：**通过后服务端在同一事务内直接更新模块**，驳回必须填写原因；申请人可撤回自己待审批的申请。已有直接编辑权限的人（PM、该模块负责人）不需要也无法走这条流程。
- 新建模块即使尚无工作项，也应在默认工作项页显示名称、负责人、空态与合法创建入口；只筛选所属模块时仍保留该空分组，按工作项内容/负责人/状态/风险/管理范围筛选时只展示匹配分组。
- 验收：创建后刷新仍能看到模块，能进入模块工作页并建立首项交付；新建工作项时负责人自动带出该模块负责人。

### F4 工作项管理（核心）
- 工作项分两类：**模块工作项**挂在功能模块下，**项目级工作项**不挂模块（`moduleId` 为空），用于承接跨模块的测试、维护、缺陷修复和上线保障。
- 工作项字段：名称、说明、类型、计划起止日期、负责人。类型为**功能开发 / 测试 / 维护 / 缺陷修复 / 其他**，默认功能开发；模块工作项负责人默认继承模块负责人，项目级工作项由 PM/管理员创建、负责人可为项目内任意有效成员。
- **状态机**：未开始 → 进行中 → 已完成；任何非完成状态可 → 已取消。v1 用“取消”保留工作项历史，不提供已产生记录工作项的物理删除。
- **交付**：工作项是最小功能交付单位，由负责人开始和确认完成。无须创建子任务，历史任务与交付资料数量不阻断完成，也不推算功能进度；兼容 progress 仅 DONE=100、其余=0。项目/模块按未取消工作项的交付完成数统计，界面显示已交付x/y。
- **异常标记**：
  - 受阻：负责人可标记/解除，须填原因；
  - 延期：自动判定（见规则），解除须改计划日期或完成工作项。
- **延期规则**：
  - 今日 > 计划结束日 且 状态 ∈ {未开始, 进行中} → 自动标"延期"；
  - 距计划结束日 ≤ 3 天且未完成 → 自动标"临近"（黄色提示）；
  - 出现延期后，工作项负责人**必须填写延期原因**，提交后自动通知 PM 与模块负责人。
- **交付物清单**：每个工作项可维护一份交付物清单，用于回答“这个工作项要交什么、还缺什么、文件在哪”。
  - 清单项含名称、状态（待提供 / 已提供）、负责人、备注和可选的排序号，可**可选关联**本工作项已上传的一个文件；文件仍走工作项级附件，不新建文件体系，也不区分“需要 / 产出”方向（归属由所属工作项表达）。v1 没有拖拽重排入口，列表按排序号与创建顺序展示。
  - 已完成 / 已取消工作项只能修改状态（补标“已提供”），不能新增、改名、改派、换文件、改备注、改排序或删除。
  - v1 不做跨工作项依赖、不强制工作项完成前清单齐全：工作项详情与时间线只显示“已提供 x/y”提示，不阻断完成工作项。
- 验收：改日期/状态后延期标记即时重算；延期工作项在时间线上红标醒目。

### F4.1 独立 Bug
- 成员（非VIEWER）报告Bug必须选择同项目功能工作项；未开始、进行中和已交付均可，已取消不可新报。默认指派给功能负责人，不再寻找进行中的BUGFIX工作项。
- Bug有独立的待修复/修复中/已解决状态、负责人、说明、处理记录与附件；已交付功能可以继续处理Bug，功能交付日期和状态保留。
- 来源功能负责人/模块负责人/PM/ADMIN可编辑和改派，执行人可改状态及保存进展记录；归档只读。来源取消后内容与状态只读，记录/附件沿用原权限。
- 修复区的进展记录使用兼容 Markdown 的编辑区：每份保存为可命名的 .md 记录，一个 Bug 可保存多份；编辑区单栏所见即所得，标题、列表、图片等直接显示为最终效果，不再分编辑和预览两栏，图片内联显示，其他文件只显示文件名、点击查看全文或下载；需要手写语法时可切到「源码」。粘贴的截图在正文内联预览，其他文件以超链接占位、点击查看或下载。粘贴的文件同时上传为本任务附件（分类「进展记录附件」），直接在「附件」页签显示；保存前可在编辑区移除本次上传，移除会同时删除该附件并去掉正文占位。已保存记录可由作者本人或任务管理者再次编辑标题与正文，更新后显示最后编辑时间与人。
- 兼容保存到tasks.kind=BUG，历史分流Bug按有效同项目related_node_id追溯来源，不更改已有id/记录/附件。状态带expectedStatus，冲突保留草稿；编辑不可更换来源或类型。

### F5 功能详情、资料与历史任务
- 默认页面为功能说明、交付资料、Bug、活动记录。交付资料同时展示交付要求与文件，按原附件权限上传/预览/下载和保留版本。
- 默认操作为开始工作、提交资料、确认交付、报告Bug。不提供通用“新建任务”作为必经步骤，也不显示任务完成率或进行中50%。
- 有已有非BUG任务时展示“历史任务”，保留原内容、状态、记录、工时和附件；原任务/看板/通知深链可读。历史任务内容/状态仍受关闭工作项限制，接口保留兼容。
- 我的工作分别展示本人负责的工作项与本人Bug，支持状态/项目/搜索/历史及服务端分页；人员负载以有效功能与Bug为主，旧人天API与周报快照保留历史。

### F6 项目时间线视图（核心页面）
- 横向时间轴按功能模块及项目级工作项分组，**每个工作项独立一行**；左侧固定名称/负责人/状态，横轴同日同位置，计划条覆盖开始和结束两日。阶段目标单独一行，支持周/月刻度、全部/本月/近四周与定位业务今天。
- 条块状态颜色与文字风险标签并用；交付物显示已提供 x/y，不改进度；超出当前范围显示日期和详情入口。点击进入工作项详情，项目上下文保持正确。
- 项目导航保持稳定；统一“新建工作项”按权限选择功能模块/项目级位置，提缺陷先展示真实接收预判。
- 验收：PM 一眼看出整个项目"现在到哪了、哪里红了"，并能区分功能工作项与跨模块事项。

### F7 看板视图
- 旧任务看板入口保留历史兼容；默认功能页不展示通用任务看板。
- 验收：Bug及历史任务共用独立任务详情页（`/nodes/{nodeId}/tasks/{taskId}`），从工作项列表、看板、我的工作、人员负载点击后直接进入对应空间，不再打开右侧抽屉；页面提供面包屑与"返回工作项"，状态提交 expectedStatus；409 刷新并保留文字草稿，不自动重试。

### F8 人员负载视图
- 跨可读有效项目汇总每人未交付、进行中、延期、本周到期的功能工作项及未解决/逾期Bug；数字可展开相同范围明细。旧任务人天字段/API保留历史，不作为主要视图。
- 验收：安排功能或Bug前可查当前责任；明细与汇总口径一致。

### F9 站内通知
- 类型（7 类）：延期预警（→PM+模块负责人）、标记受阻（→PM+模块负责人）、工作项完成（→PM）、任务指派（→执行人）、周报发布（→项目成员）、模块变更待审批（→PM）、变更审批结果（→申请人）。
- 全局通知入口显示真实未读数；类型中文化、已读/未读、分页和全部已读；任务分派与周报通知直达对应任务/周。
- 验收：工作项填完延期原因，PM 铃铛 +1 且可点击跳转到该工作项。

### F10 周报
- 系统按自然周自动生成**草稿**：本周完成工作项 / 延期·受阻工作项 / 新增工作项与任务 / 下周到期工作项 / 工时汇总。本周实际人天按工时明细的工作日期归周；本周计划人天为截止日落在本周的任务计划人天之和。
- PM 可编辑补充"风险与说明"，发布后项目成员可见并收到通知；历史周报归档可查。
- 验收：周报内容来自真实数据，不重复手工统计。

### F11 权限（详见第 8 节权限矩阵）
- 只读观察者可看所有项目与周报，不可修改业务数据；允许将自己的通知标为已读；
- 成员仅可操作自己被指派的任务与自己负责的工作项；
- PM 管理项目内一切；管理员全局。

### F12 文档与附件
- **项目级**：PM 按分类维护项目文档，覆盖立项与计划、需求、设计规范、测试质量、发布运维、验收收尾、管理过程七组；普通成员与只读观察者可查看下载。
- **模块级**：模块负责人上传本模块的设计文档、流程图、开发记录等过程痕迹；项目成员可下载。
- **工作项级**：模块下的功能工作项可以挂自己的文件（工作项设计说明、流程图、接口说明、自测记录、截图、交付物），由工作项负责人、模块负责人或 PM 上传，用于留下该功能实现的过程证据。
- **任务级**：任务的交付物与参考资料也走同一套附件（任务交付物、参考资料、进展记录附件、其他任务文件），由任务执行人或其上级上传。进展记录里粘贴的图片/文件即落在「进展记录附件」，记录正文只保存引用，不重复存文件。
- **全项目汇总**：项目文档页的「全部文件」汇总项目级、模块级、工作项级、任务级四层文件，标明归属并可按来源筛选。
- **在线查看**：PDF、图片（png/jpg/jpeg/gif/webp）、文本类（txt/md/csv）、Word（docx）、Excel（xlsx）可在弹窗内直接预览，不必下载。预览走浏览器本地渲染，不需要服务端转换服务；docx/xlsx 超过 20MB 只提示下载。
- 不在预览白名单内的格式（svg、doc/xls/ppt、drawio、压缩包等）**列表里不显示「预览」按钮**，只能下载；SVG 因可携带脚本且 blob 文档继承应用源，明确不做在线预览。
- 同名文件再次上传形成新版本（历史版本保留），删除为软删除、磁盘文件保留，用于追溯。
- 分类为系统预置字典（参考 GB/T 8567-2006 文档主线归并），调整分类不改表结构。
- 验收：上传后可下载且内容一致、可在线预览；只读账号能下不能传；归档项目只能看。

## 6. 数据模型

### 6.1 实体关系（文字版）

```
users（用户，含全局角色）
  │
  ├─ project_members（项目成员，含项目内职务 PM/MEMBER）
  │      └─ projects（项目）
  │           ├─ modules（模块，owner_id → 模块负责人）
  │           │     └─ nodes（工作项，owner_id → 工作项负责人）
  │           │           ├─ tasks（任务，assignee_id → 执行人）
  │           │           │    ├─ task_notes（任务进展记录）
  │           │           │    └─ task_work_logs（逐日实际人天，界面已不再录入，数据保留）
  │           │           ├─ node_deliverables（工作项交付物清单，可选关联一个工作项级附件）
  │           │           ├─ module_change_requests（模块变更申请，PM 审批后自动改模块）
  │           │           └─ node_logs（工作项状态/变更日志）
  │           ├─ attachments（文档附件，owner_type = PROJECT/MODULE/NODE/TASK）
  │           └─ weekly_reports（周报）
  └─ notifications（通知，user_id → 接收人）
```

### 6.2 表结构基线（MySQL 8）

完整表、字段和约束统一见 [database.sql](./database.sql)，演示账号与样例数据见 [demo_seed.sql](./demo_seed.sql)；这里不重复维护第二份 DDL。核心实体为 users、projects、project_members、modules、nodes、tasks、task_notes、task_work_logs、node_deliverables、module_change_requests、attachments、node_logs、notifications、weekly_reports。模块与工作项各有一位负责人，任务有一位执行人。项目 PM 由 project_members 中的 PM 职务表达。

**规则实现要点**：
- 延期与临近到期根据工作项状态、计划结束日和业务时区的当天日期实时计算，不在工作项表保存容易过期的布尔值。
- 工作项交付进度只由状态派生：已交付为 100%，未开始、进行中、已取消为 0%；历史任务、资料数量和 Bug 不参与。
- 模块/项目完成率 = 已交付工作项数 ÷ **未取消**工作项数；界面优先显示“已交付 x/y”。
- 工作项负责人确认交付时写入业务时区的实际结束日；不要求历史任务全部完成。进度不落库，读取时实时派生。

## 7. 页面设计与原型说明

现有原型含 10 个独立 HTML 页面和一个带内存态交互的 `prototype/index.html`，都使用演示数据；交互状态在刷新后重置。正式 v1 还需要补管理员账号管理页：

| # | 页面 | 用途 | 核心元素 |
|---|---|---|---|
| P1 | 登录页 | 登录入口 | 用户名/密码/登录按钮 |
| P2 | 我的项目 | 项目卡片列表 | 卡片：项目名、进度环、工作项统计（完成 x/y）、延期红点、周报入口 |
| P3 | 项目概览与时间线 | 交付与风险 | 概览先看风险原因、近期目标及计划；时间线另页按工作项独立行显示日期轴 |
| P4 | 模块视图与工作页 | 模块卡片、工作项表单 | 每模块：负责人、进度、工作项数、延期数；进入模块后可填写工作项信息并进入工作项详情 |
| P5 | 功能工作项详情 | 最小交付单位 | 功能说明、交付资料、Bug、活动记录；开始/确认交付；有旧任务时显示历史入口 |
| P6 | 历史任务看板 | 旧路由兼容 | 旧任务可读取，按原关闭/归档规则维护；不提供默认新建通用任务入口 |
| P7 | 人员负载 | 当前交付责任 | 人员 × 未交付/进行中/延期/本周到期工作项、未解决/逾期Bug，可展开明细 |
| P8 | 通知中心 | 站内通知 | 列表：类型图标+标题+时间+未读标记，点击跳转 |
| P9 | 周报 | 汇报 | 本周草稿（自动汇总块+PM 补充说明）+ 历史周报列表 |
| P10 | 项目管理 | 模块与设置 | 独立模块列表维护名称、描述、负责人；设置维护基本信息、项目阶段性目标和成员 |
| P11 | 账号管理 | 管理员专用；现有原型未覆盖 | 创建账号、修改角色、停用账号、重置密码 |

**假数据场景**（原型统一使用）：
- 原型展示 6 个业务用户；SQL 演示数据另含 1 个管理员账号供 F1 验收。
- 2 个项目：「商城系统开发」（活跃，含 1 个延期工作项、1 个受阻工作项、1 个临近工作项）、「移动端 APP 改版」（新立项）。
- 商城项目：3 模块、11 个工作项、21 个任务，覆盖主要状态与异常标记，用于演示红黄预警。

## 9. v1 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Spring Boot 3.x + Spring Security + JWT + MyBatis-Plus | 用户偏好 Java；生态成熟、招人易；10 人自托管单体足够 |
| 前端 | Vue 3 + Element Plus + Vite | 组件齐全（表格/日期/进度条/铃铛），开发快 |
| 数据库 | MySQL 8 | 用户偏好；表结构简单，无需复杂检索 |
| 时间线视图 | v1 自绘（CSS Grid/SVG 甘特条） | 免引入重型甘特库；后续可换 Frappe Gantt |
| 部署 | 单体 jar + Nginx（可选 Docker Compose） | 单机自托管最简路径 |

> 说明：国产开源 PM 主流 PHP（禅道/DooTask 等），但产品模型与语言无关；Java 方案在自托管、内网、10 人量级下无劣势。

## 10. 原型制作计划

1. 按第 7 节页面清单制作 10 个静态 HTML 页面，统一导航（左侧菜单 + 顶栏铃铛）。
2. 假数据内联在页面中；页面间用超链接模拟跳转。
3. 交付后逐页评审，确认后再进入开发阶段（数据库脚本 + 后端 + 前端）。
