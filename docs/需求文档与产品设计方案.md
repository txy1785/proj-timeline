# 项目进度管理系统 —— 需求文档与产品设计方案（v0.1）

> 工作名：proj-timeline，暂定中文名「项目时间线」
> 状态：v1 需求基线 ｜ 交付顺序：本设计文档 → 静态 HTML 原型 → 契约与执行计划评审 → 开发
> 开发契约以本文件的业务规则、`接口设计.md` 的 HTTP 契约和 `database.sql` 的物理表结构为准；`开发文档.md` 只说明实现方式，不能覆盖前三者。

## 1. 背景与目标

**背景**：10 人以内团队，多项目并行。需要一个自托管的进度管理系统，解决三个痛点：

1. 项目的**当前进度**一眼可见（现在靠问、靠开会）；
2. 进度**节点化**：每个里程碑有明确时间、状态、负责人；
3. **责任明确**：节点谁负责、模块谁负责、任务分给谁，一清二楚。

**目标（v1）**：聚焦"进度管理"一件事——项目 / 模块 / 节点（里程碑）/ 任务 / 人员 / 工时 / 周报。**不做**需求池、Bug 管理（列入后续迭代）。

**核心设计原则**（来自 GitHub 调研，详见两份调研报告）：

| 原则 | 说明 | 来源 |
|---|---|---|
| 节点是独立实体 | 节点 = 名称 + 计划/实际日期 + 状态 + 负责人 + 挂任务，进度向下聚合 | GitHub Milestone、Plane Cycle、禅道里程碑 |
| 负责人双轨 | 负责人（对结果负责）+ 指派人（执行），任务按模块**自动带出**默认负责人、可改派 | 禅道"模块默认指派人"、Plane Module.Lead |
| 状态与异常分离 | 状态 = 未开始/进行中/已完成/已取消；"受阻""延期"是**可叠加的异常标记** | 商业产品常见做法（延期=计划 vs 实际偏差） |
| 延期闭环 | 到期自动红/黄预警 → 负责人填原因 → 自动通知 PM | 禅道、Teambition 汇报模式 |

## 2. 调研摘要（结论已合并）

**国际高星产品**（报告：[research/开源项目管理系统调研报告.md](../research/开源项目管理系统调研报告.md)）：
- **Plane**（59.5k⭐，最活跃）：Module（带 Lead 负责人）+ Cycle + Issue 父子 + 甘特依赖，进度自动聚合——"模块+负责人"最直接样板。
- **OpenProject**（15.8k⭐）：一切皆 Work Package，Phase/Milestone 是 Type 之一，角色权限矩阵最强。
- **Taiga**（≈13k⭐）：冲刺时间盒 + Epic→Story→Task 三层，已进入维持期。
- 其余（Focalboard 已停维、Vikunja、Leantime、Huly、Wekan、Kanboard）各有取舍，结论：**节点独立实体 + 负责人双轨**是主流。

**国产产品**（报告：[pm-systems-research.md](../pm-systems-research.md)）：
- **禅道 ZenTao**：里程碑/阶段/迭代三形态；模块树设**默认指派人**（新任务自动带出）；工时预估/消耗/剩余三值；燃尽图；周报对象化——与我们的目标最接近的参考。
- **ONES / Worktile / Teambition / TAPD**：术语统一为 负责人/处理人+抄送、里程碑挂发布计划、阶段+交付物、工时统计、甘特+报表。
- **结论**：国产开源 PM 主流 PHP，但技术栈不影响产品模型；10 人自托管用 Java + MySQL 完全可行。

## 3. 用户与角色

### 3.1 角色设计（10 人团队，一人可多职）

| 角色 | 类型 | 职责 | 系统内典型操作 |
|---|---|---|---|
| 管理员 | 全局角色 | 管用户账号、系统设置 | 建账号、设全局角色、删数据 |
| 普通用户 | 全局角色 | 干活 | 被分配后操作 |
| 只读观察者（老板/管理层） | 全局角色 | 只看全局，不操作 | 看总览、周报、延期预警 |
| PM（项目经理） | **项目内职务** | 对项目整体结果负责 | 建项目、建模块、建节点、指定负责人、确认周报 |
| 模块负责人 | **项目内职务** | 对模块负责 | 管模块下节点/任务，向 PM 汇报 |
| 节点负责人 | **项目内职务** | 对节点负责 | 更新节点状态/百分比、填延期原因、分任务 |
| 成员（执行人） | **项目内职务** | 具体干活 | 认领任务、更新任务状态、填实际人天 |

**关键约定**：全局角色只有三种（管理员/普通用户/只读）；PM、模块负责人、节点负责人是**项目内的职务**，同一个人在不同项目可以担任不同职务（A 项目的 PM、B 项目的节点负责人）。

### 3.2 负责人双轨（简化版）

- 每个**模块**有一个**负责人**（模块负责人，由 PM 指定）。
- 每个**节点**有一个**负责人**，**新建时自动带出所属模块的负责人**，可改派。
- 每个**任务**有一个**负责人**（执行人），**新建时自动带出所属节点的负责人**，可改派。
- v1 均为单人负责（问责清晰），预留"多负责人/抄送"字段扩展。

## 4. 术语表

| 术语 | 含义 |
|---|---|
| 项目 Project | 一次有明确目标的交付集合，有 PM 和成员 |
| 模块 Module | 项目的功能块划分（如"用户与登录""订单与支付"），有模块负责人 |
| 阶段性目标 Stage Target | 直接属于项目的关键目标，包含目标名称、说明和目标日期，与模块无关 |
| 节点 / 里程碑 Node | 模块下的时间检查点（如"5/10 接口联调完成"），有负责人、状态、计划/实际日期 |
| 任务 Task | 节点下最小执行单元，有负责人、状态、工时 |
| 负责人 | 对结果负责的人（模块负责人/节点负责人/任务执行人） |
| 计划日期 | 节点/任务原定日期；**实际日期** = 真实发生日期，用于计算延期 |
| 状态 | 节点的 4 态：未开始 / 进行中 / 已完成 / 已取消 |
| 异常标记 | 叠加在状态上的标记：**受阻**（有阻塞问题）、**延期**（计划晚于实际） |
| 进度 | 节点百分比 0-100（手动维护）；项目进度 = 节点进度聚合 |
| 工时 | 计划人天（估的）与按工作日期逐日记录的实际人天（花的），二者对比看偏差 |
| 通知 | 站内通知（延期预警 / 指派 / 完成 / 周报） |
| 周报 | 系统按本周变化自动生成草稿，PM 确认后发布的汇报 |

## 5. 功能需求

### F1 登录与账号
- 管理员创建账号（用户名/姓名/密码/全局角色），账号可停用；停用不删除历史责任、工时和日志。
- 登录后进入「我的项目」列表。
- 验收：普通用户看不到账号管理入口；停用账号无法登录。

### F2 项目管理
- 有效的普通用户或管理员可创建项目：名称、代号、描述、项目开始日期（必填）、项目完成日期（可空）；创建者自动成为 PM。项目不再使用时归档，保留周报和责任历史；PM/管理员可恢复为活跃状态，归档期间项目业务数据只读。
- PM/管理员可在项目内维护多个阶段性目标。目标日期不得早于项目开始日期；项目完成日期存在时不得晚于完成日期。
- 项目详情页含：总进度、节点统计（总数/已完成/进行中/延期/受阻）、模块列表、时间线、周报入口。
- 项目成员管理：PM 添加/移出成员；新建项目者自动成为该项目 PM，每个项目恰有一个 PM，转交 PM 须先把接任者加入项目。
- 验收：项目卡片上进度环 + 延期红点数一目了然。

### F3 模块管理
- 项目下维护模块列表（v1 一层，预留多级）：名称、描述、**模块负责人**。模块用于功能拆分，不承载项目阶段目标。
- PM 可增删改模块、指定/变更模块负责人；含节点的模块不可删除。
- 模块负责人进入自己负责的模块后，可查看节点列表并填写节点名称、说明、计划起止日期和负责人；创建后进入节点详情继续维护状态、进度和任务。
- 验收：新建节点时负责人自动带出该模块负责人。

### F4 节点管理（核心）
- 节点挂模块下：名称、描述、计划起止日期、负责人（默认=模块负责人）。
- **状态机**：未开始 → 进行中 → 已完成；任何非完成状态可 → 已取消。v1 用“取消”保留节点历史，不提供已产生记录节点的物理删除。
- **进度**：节点负责人手动维护百分比（0-100），与状态联动提示（状态=已完成时进度强制 100）。
- **异常标记**：
  - 受阻：负责人可标记/解除，须填原因；
  - 延期：自动判定（见规则），解除须改计划日期或完成节点。
- **延期规则**：
  - 今日 > 计划结束日 且 状态 ∈ {未开始, 进行中} → 自动标"延期"；
  - 距计划结束日 ≤ 3 天且未完成 → 自动标"临近"（黄色提示）；
  - 出现延期后，节点负责人**必须填写延期原因**，提交后自动通知 PM 与模块负责人。
- 验收：改日期/状态后延期标记即时重算；延期节点在时间线上红标醒目。

### F5 任务管理
- 任务挂节点下：名称、负责人（默认=节点负责人）、状态（待完成/进行中/已完成）、截止日、计划人天。
- 任务**不要求录工时**，直接用状态标记进度；完成时记录完成时间，改回未完成会清空完成时间。
- 任务带两类补充信息：**附件**（交付物与参考资料，走统一附件体系，可在项目文档页汇总查看）和**记录**（追加式进展记录，写完成思路与结果，也可当备注，带作者与时间）。
- 逐日工时的数据与接口保留（历史周报依赖它），但界面不再提供录入口。
- 验收：节点详情能看到任务状态、记录条数与附件，任务详情弹窗可直接改状态并补记录。

### F6 项目时间线视图（核心页面）
- 横向时间轴（甘特风格），**按模块分组泳道**，节点以条块呈现。
- 条块颜色 = 状态；延期红、临近黄、受阻紫标；条上显示负责人姓名与进度。
- 顶部筛选：按模块 / 负责人 / 状态 / 时间范围。
- 验收：PM 一眼看出整个项目"现在到哪了、哪里红了"。

### F7 看板视图
- 节点内任务看板：待办 / 进行中 / 已完成 三列。
- 验收：拖动改列（原型阶段静态展示）。

### F8 人员负载视图
- 跨项目汇总每人：负责的节点（进行中/延期数）、任务（待办/进行中数）、选定周到期项、所有未完成任务的计划人天及该周到期任务的计划人天。
- 验收：分配任务前可查某人是否过载。

### F9 站内通知
- 类型：延期预警（→PM+模块负责人）、任务指派（→执行人）、节点完成（→PM）、周报发布（→项目成员）。
- 右上角铃铛 + 未读数；已读/未读。
- 验收：节点填完延期原因，PM 铃铛 +1 且可点击跳转到该节点。

### F10 周报
- 系统按自然周自动生成**草稿**：本周完成节点 / 延期·受阻节点 / 新增节点与任务 / 下周到期节点 / 工时汇总。本周实际人天按工时明细的工作日期归周；本周计划人天为截止日落在本周的任务计划人天之和。
- PM 可编辑补充"风险与说明"，发布后项目成员可见并收到通知；历史周报归档可查。
- 验收：周报内容来自真实数据，不重复手工统计。

### F11 权限（详见第 8 节权限矩阵）
- 只读观察者可看所有项目与周报，不可修改业务数据；允许将自己的通知标为已读；
- 成员仅可操作自己被指派的任务与自己负责的节点；
- PM 管理项目内一切；管理员全局。

### F12 文档与附件
- **项目级**：PM 按分类维护项目文档，覆盖立项与计划、需求、设计规范、测试质量、发布运维、验收收尾、管理过程七组；普通成员与只读观察者可查看下载。
- **模块级**：模块负责人上传本模块的设计文档、流程图、开发记录等过程痕迹；项目成员可下载。
- **节点级**：模块下的功能节点可以挂自己的文件（节点设计说明、流程图、接口说明、自测记录、截图、交付物），由节点负责人、模块负责人或 PM 上传，用于留下该功能实现的过程证据。
- **全项目汇总**：项目文档页的「全部文件」汇总项目级、模块级、节点级三层文件，标明归属并可按来源筛选。
- 同名文件再次上传形成新版本（历史版本保留），删除为软删除、磁盘文件保留，用于追溯。
- 分类为系统预置字典（参考 GB/T 8567-2006 文档主线归并），调整分类不改表结构。
- 验收：上传后可下载且内容一致；只读账号能下不能传；归档项目只能看。

## 6. 数据模型

### 6.1 实体关系（文字版）

```
users（用户，含全局角色）
  │
  ├─ project_members（项目成员，含项目内职务 PM/MEMBER）
  │      └─ projects（项目）
  │           ├─ modules（模块，owner_id → 模块负责人）
  │           │     └─ nodes（节点，owner_id → 节点负责人）
  │           │           ├─ tasks（任务，assignee_id → 执行人）
  │           │           │    └─ task_work_logs（逐日实际人天）
  │           │           └─ node_logs（节点状态/变更日志）
  │           └─ weekly_reports（周报）
  └─ notifications（通知，user_id → 接收人）
```

### 6.2 表结构基线（MySQL 8）

完整表、字段和约束统一见 [database.sql](./database.sql)，演示账号与样例数据见 [demo_seed.sql](./demo_seed.sql)；这里不重复维护第二份 DDL。核心实体为 users、projects、project_members、modules、nodes、tasks、task_work_logs、node_logs、notifications、weekly_reports。模块与节点各有一位负责人，任务有一位执行人。项目 PM 由 project_members 中的 PM 职务表达。

**规则实现要点**：
- 延期与临近到期根据节点状态、计划结束日和业务时区的当天日期实时计算，不在节点表保存容易过期的布尔值。
- 项目进度 = 所有**未取消**节点进度的简单平均（v1；迭代可改工时加权）。
- 节点完成时强制 `progress=100`，`actual_end=今天`。

## 7. 页面设计与原型说明

现有原型含 10 个独立 HTML 页面和一个带内存态交互的 `prototype/index.html`，都使用演示数据；交互状态在刷新后重置。正式 v1 还需要补管理员账号管理页：

| # | 页面 | 用途 | 核心元素 |
|---|---|---|---|
| P1 | 登录页 | 登录入口 | 用户名/密码/登录按钮 |
| P2 | 我的项目 | 项目卡片列表 | 卡片：项目名、进度环、节点统计（完成 x/y）、延期红点、周报入口 |
| P3 | 项目概览·时间线 | **核心** | 顶部筛选；时间轴按模块泳道分组，节点条（状态色+延期红/临近黄/受阻紫+负责人名+进度%）；图例 |
| P4 | 模块视图与工作页 | 模块卡片、节点表单 | 每模块：负责人、进度、节点数、延期数；进入模块后可填写节点信息并进入节点详情 |
| P5 | 节点详情 | 节点操作页 | 信息区（名称/模块/负责人/计划·实际日期/状态/进度条）；操作区（状态流转按钮、百分比输入、受阻标记、延期原因表单）；任务列表、逐日工时录入与更正、工时合计、变更日志 |
| P6 | 任务看板 | 节点内看板 | 待办/进行中/已完成三列，卡片含负责人与工时 |
| P7 | 人员负载 | 跨项目汇总 | 表格：人员 × 负责节点/任务/本周到期/延期数/计划人天 |
| P8 | 通知中心 | 站内通知 | 列表：类型图标+标题+时间+未读标记，点击跳转 |
| P9 | 周报 | 汇报 | 本周草稿（自动汇总块+PM 补充说明）+ 历史周报列表 |
| P10 | 项目管理 | 设置 | 基本信息、项目阶段性目标、成员管理、一层模块列表维护（含负责人） |
| P11 | 账号管理 | 管理员专用；现有原型未覆盖 | 创建账号、修改角色、停用账号、重置密码 |

**假数据场景**（原型统一使用）：
- 原型展示 6 个业务用户；SQL 演示数据另含 1 个管理员账号供 F1 验收。
- 2 个项目：「商城系统开发」（活跃，含 1 个延期节点、1 个受阻节点、1 个临近节点）、「移动端 APP 改版」（新立项）。
- 商城项目：3 模块、11 个节点、21 个任务，覆盖主要状态与异常标记，用于演示红黄预警。

## 8. 权限矩阵

| 操作 | 管理员 | 只读观察者 | PM（该项目） | 模块负责人 | 节点负责人 | 普通成员 |
|---|---|---|---|---|---|---|
| 看项目/时间线/周报 | ✅ | ✅（只读） | ✅ | ✅ | ✅ | ✅ |
| 建/改/归档/恢复项目、增删改模块 | ✅ | ❌ | ✅ | ❌ | ❌ | ❌ |

## 9. v1 技术方案

| 层 | 选型 | 理由 |
|---|---|---|
| 后端 | Spring Boot 3.x + Spring Security + JWT + MyBatis-Plus | 用户偏好 Java；生态成熟、招人易；10 人自托管单体足够 |
| 前端 | Vue 3 + Element Plus + Vite | 组件齐全（表格/日期/进度条/铃铛），开发快 |
| 数据库 | MySQL 8 | 用户偏好；表结构简单，无需复杂检索 |
| 时间线视图 | v1 自绘（CSS Grid/SVG 甘特条） | 免引入重型甘特库；后续可换 Frappe Gantt |
| 部署 | 单体 jar + Nginx（可选 Docker Compose） | 单机自托管最简路径 |

> 说明：国产开源 PM 主流 PHP（禅道/DooTask 等），但产品模型与语言无关；Java 方案在自托管、内网、10 人量级下无劣势。

## 10. 原型制作计划

1. 按第 7 节页面清单制作 10 个静态 HTML 页面，统一导航（左侧菜单 + 顶栏铃铛）。
