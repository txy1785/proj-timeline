## 后端与前端冻结约定

- `GET /api/context` → `{businessDate,timeZone,unreadCount}`，日期由 Clock/APP_TIME_ZONE 得出。
- `GET /api/workspace/tasks` → `{list,total,page,size,businessDate,timeZone,counts:{open,doing,overdue,done}}`。默认本人；`scope=OPEN|DONE|HISTORY|WORKLOAD|WORKLOAD_PLAN`，支持 `status,projectId,q,page,size,assigneeId,dueWeek`。显式 assigneeId 仅用于可读项目范围内人员负载展开，前端标题必须与“我的任务”区分；WORKLOAD 与原负载统计范围匹配。行在 Task 基础上返回 projectId/projectName/nodeName/projectStatus/nodeStatus/overdue。
- `GET /api/workspace/management` → `{nodes,requests,nodeTotal,requestTotal}`。nodes 为本人有管理职责的有效项目中的延期/受阻工作项，requests 为本人可审批的待审批模块申请；数组上限须有总数提示，不能静默遗漏。
- `GET /api/workspace/work-items` → PageResponse<NodeItem+projectName>，用于负载工作项数展开，支持 `ownerId,scope=ACTIVE|OVERDUE,page,size`；按可读项目过滤，与既有负载数字对应。
- `GET /api/projects/{id}/bug-routing?relatedNodeId=` → `{canSubmit,nodeId?,nodeName?,ownerId?,ownerName?,message}`。预判复用提交分流规则，提交仍重新检查，GET 不创建工作项或任务。
- 共享 `TaskDrawer`：`v-model`、`:node-id`、`:task-id`；组件自行按合法工作项加载任务、成员、记录；`@updated` 通知来源刷新。支持 `?task=<id>` 的工作项详情深链。任务抽屉的文字与状态动作分开保存，关闭保护草稿。
- 共享 `TaskFormDialog`：`v-model`、`:node-id`、`:task`（编辑可选）、`:members`、`:default-owner-id`、`:work-items`（关联下拉）、`@saved`。保持旧任务折叠字段原值，不隐式填人天。
- 共享 `useProjectContext(projectId)`：返回 `project,members,loading,error,businessDate,isPm,canCreateWorkItem,refresh`；项目外壳与页面共用缓存并隔离账号。
- 公共权限使用 `utils/permissions.ts`；工作项中文状态复用 `utils/workItem.ts` 新增的状态常量；业务日期使用 `utils/date.ts` 的日期字符串/UTC运算，禁止浏览器当前时间判断业务“今天”。

以上是本轮实施接口约定，正式 HTTP 契约由 M1 同步到接口设计，运行期 OpenAPI 类型在集成后的后端重新生成。
