# 功能交付模型验收

2026-10-27 用户授权将工作项作为最小功能交付单位。正式需求见 [功能交付模型实施计划](../功能交付模型实施计划.md) 和 [接口契约](../接口设计.md)。本次覆盖旧的默认通用任务层与任务完成率规则。

## 最终行为

- 默认工作项页面展示功能说明、交付资料、Bug、活动记录；交付资料同时展示要求与实际图纸/文档/附件。有旧记录时额外显示历史任务，保留旧看板、说明、记录、工时和附件。
- 工作项负责人开始工作并确认交付。功能交付不由历史任务、资料数量或Bug数推算，不显示进行中50%；项目/模块以已交付x/y为主，取消项不进分母。
- 成员可对未开始、进行中、已交付功能报告Bug；关联功能必选，默认由功能负责人处理。Bug独立修复、改派和记录，已交付功能不必重开；已取消不可新报或改Bug内容/状态，归档和VIEWER只读。
- 我的工作以本人工作项与本人Bug为主，保留管理事项和历史任务。人员负载展示有效项目的功能交付责任和Bug，数字按同一负责人/自然周/延期范围展开。
- 兼容使用tasks.kind=BUG和原记录/附件，无表结构、迁移或批量数据改写。旧分流Bug在同项目内追溯原功能授权，不能用关联字段扩大读取或写入范围。

## 审核修复与兼容边界

1. 旧createTask(kind=BUG)统一委托报告Bug来源规则；非BUG历史任务禁止转换BUG，编辑下拉排除BUG。取消来源、默认功能负责人和原记录不变均有回归。
2. 关闭功能保留底层受阻历史，但列表、排期、我的工作通过共享hasWorkItemRisk只展示未关闭功能的当前风险，避免风险数字与筛选不一致。

既有历史任务没有转换为工作项或删除；如需回退前后端代码，无需回滚数据库。回退旧版后，已交付功能的Bug仍可读取，但旧版状态限制不支持新的交付后修复流程。已发布周报保留原快照；旧任务人天接口仍可读取。

构建保留现有Element Plus主包超过500kB提示。验证基于Chromium，未覆盖Firefox/Safari和真实团队长期使用统计；本轮未验证Docker部署。
