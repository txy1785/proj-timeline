# 复用库：可复用方法与设计模式

> **写代码前先查这里，新建可复用项必须登记在这里。** 维护规则见 [AGENTS.md](../AGENTS.md) 的「复用库与防重复编码」一节。
> 目的：让后续开发（包括 AI 会话）知道项目里已有哪些方法、封装和模式可直接使用，避免重复编写。

## 0. 收录标准

- 同一逻辑已在 **≥2 处**使用，或预期会被多处使用（工具类、通用封装、公共组件）；
- 跨模块通用的**业务口径**（日期、权限、状态、进度、通知、周报）；
- 前端通用封装（请求、会话、路由守卫、样式 token、页面骨架）；
- 判断口诀：**下次写同类需求时，能不能直接引用现成的？** 能 → 必须登记。

## 1. 后端 · 响应与异常

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `ApiResponse<T>` | `backend/src/main/java/com/projtimeline/common/ApiResponse.java` | 统一响应包 `{code,msg,data}` | `ApiResponse.ok(data)`；失败由 `BusinessException` + `GlobalExceptionHandler` 输出 | 不要手写 JSON 响应结构 |
| `PageResponse<T>` | `common/PageResponse.java` | 分页结构 `{list,total,page,size}` | `new PageResponse<>(list, total, page, size)` | 列表接口统一使用 |
| `BusinessException` | `common/BusinessException.java` | 业务异常（携带 HTTP 状态与错误码） | `throw BusinessException.badRequest("x")`；工厂：`badRequest`(4000/400)、`unauthorized`(4001/401)、`forbidden`(4003/403)、`notFound`(4004/404)、`conflict`(4090/409)、`internal`(5000/500) | 不要用裸 `RuntimeException` 表达业务错误；不要用构造器直接拼错误码 |
| `GlobalExceptionHandler` | `common/GlobalExceptionHandler.java` | 全局异常 → 统一响应（`@RestControllerAdvice`） | 自动生效；参数校验失败 4000、数据约束冲突 4090、未预期异常 5000 | 新增异常类型时在此统一映射 |

## 2. 后端 · 业务日历与参数

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `BusinessCalendar` | `common/BusinessCalendar.java` | `Clock` 驱动的延期/临近判定、自然周计算 | `nodeFlags(status, planEnd, blocked, clock)` → `Map{overdue,near,blocked}`；`week(date)` → `[周一, 周日]` | 禁止 `LocalDate.now()` 裸用；禁止数据库 `CURRENT_DATE` 代替业务“今天” |

## 3. 后端 · 权限与认证

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `PermissionService` | `security/PermissionService.java` | 项目业务写操作前置校验（账号、项目、职务、归档） | `current()`；`requireProjectRead/requireProjectActive(id)`；`requireProjectManager(id)`；`requireModuleManager(moduleId)`；`requireNodeManager(nodeId)`；`requireTaskManager(taskId, allowAssignee)`；`requireAssignable(projectId, userId)`；`projectForNode/Task/Report(id)` | **所有写接口必须调用**；VIEWER 一律拒绝；不要只靠前端隐藏按钮 |
| `CurrentUser` | `security/CurrentUser.java` | 当前用户主体 record | `record(id, username, name, globalRole)`；`isAdmin()/isViewer()` | 通过 `PermissionService.current()` 获取，不要自行从 SecurityContext 强转 |
| `JwtService` | `security/JwtService.java` | JWT 签发/校验（HS256，默认 8h） | `issue(userId)` → `Token(token, expiresAt)`；`verifyAndGetUserId(token)` | 密钥 ≥32 字节；不要自己实现 JWT 解析 |
| `JwtAuthenticationFilter` | `security/JwtAuthenticationFilter.java` | 每请求校验账号启用状态并注入 SecurityContext | 自动装配；停用账号下次请求即 401 | 不要绕过该过滤器自行校验 token |
| `AppProperties` | `config/AppProperties.java` | 配置 record | `AppProperties(timeZone, jwtSecret, jwtHours, bootstrapAdmin)`；构造注入即用 | 时区默认 `Asia/Shanghai`，JWT 时长默认 8h |
| `AdminBootstrapRunner` | `config/AdminBootstrapRunner.java` | 首次启动创建管理员 | `--app.bootstrap-admin=true` 启动；已存在 ADMIN 时拒绝执行；密码长度 8..72 | 不要在其他地方创建管理员账号 |

## 4.1 后端 · 文件存储与文档

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `FileStorage` | `backend/src/main/java/com/projtimeline/file/FileStorage.java` | 文件存储抽象：`put/get/delete`，本地磁盘实现，后续可替换为 MinIO/S3 | 构造注入接口后 `storage.put(in, size, ext)` 返回相对 key | 换存储只加实现、改配置；不要在业务里直接调 `java.nio.file` |

| `DocumentCatalog` | `file/DocumentCatalog.java` | 文档分类字典（项目级 7 组 / 模块级 1 组） | `DocumentCatalog.find(ownerType, code)`、`all()` | 调整分类只改这里，表结构和接口不变；历史记录按 code 保留 |
| `MediaTypes` | `file/MediaTypes.java` | 服务端按扩展名推导 Content-Type，并判断哪些类型可内联预览 | `MediaTypes.of("pdf")`；`MediaTypes.inlineAllowed(type)` | **不要采用客户端 multipart 声明的 Content-Type**；只有 pdf/png/jpg/gif/webp 可内联，svg/txt 一律下载 |
| `AttachmentService` | `file/AttachmentService.java` | 文档上传/列表/下载/软删除的权限与版本口径 | `upload/list/download/delete`；返回行已带 `categoryName` | 上传：项目级 `requireProjectManager`、模块级 `requireModuleManager`；删除：上传者本人或对应管理者；删除是软删除，磁盘文件保留 |

## 5. 业务口径（模式级，不写代码也必须遵守）

- **实体层级**：项目 → 模块 → 节点 → 任务；阶段性目标属于**项目**；模块只做功能划分，无阶段日期。
- **延期/临近**：`BusinessCalendar.nodeFlags` 是唯一口径；未开始/进行中且 `planEnd < today` → overdue；`0~3` 天内 → near。服务端实时计算，前端只展示。
- **进度聚合**：项目进度 = 未取消节点的进度直接平均；节点完成强制进度 100%。
- **负责人双轨与继承**：模块负责人 → 节点负责人 → 任务执行人；新建节点默认继承模块负责人，新建任务默认继承节点负责人；改派目标须为项目内有效且非 VIEWER 成员（`requireAssignable` 校验）。
- **通知触发（5 类）**：延期原因提交、标记受阻、节点完成、任务指派、周报发布。
- **周报**：未发布周实时计算；发布时写入 JSON 快照；按周一至周日归周。
- **权限矩阵**：`ADMIN` 全量；`VIEWER` 只读且不得写业务数据；`USER` 仅所属项目。项目内 PM > 模块负责人 > 节点负责人 > 任务执行人。

## 6. 前端 · 请求与类型

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `http` / `api<T>()` | `frontend/src/api/client.ts` | Axios 实例（baseURL `/api`、15s 超时）+ 统一请求封装 | `api<T>(method, url, data?, params?)` → 直接返回 `data`；`code!==0` 抛错；401 自动清会话并跳登录 | 视图里不要直接使用 axios/fetch；错误统一 `ElMessage.error((e as Error).message)` |
| `types.ts` | `frontend/src/api/types.ts` | 领域类型契约（`GlobalRole/ProjectStatus/NodeStatus/TaskStatus` 枚举与 `User/Project/NodeItem/ModuleItem/Task/Report/Notification` 等接口） | 新接口先更新类型，再写视图 | 不要内联 `any` 对象字面量 |
| `schema.d.ts` | `frontend/src/api/schema.d.ts` | OpenAPI 运行期类型 | 后端接口变更后 `npm --prefix frontend run api:types` 重新生成 | 不要手改该文件 |
| `upload()` | `frontend/src/api/client.ts` | multipart 上传，独立 5 分钟超时（默认 15s 不够） | `await upload<T>('/attachments', formData)` | 不要自己 new FormData 配 axios；不要改全局超时 |
| `download()` | `frontend/src/api/client.ts` | blob 下载，Authorization 头由拦截器带上 | `await download(\`/attachments/${id}/content\`, 文件名)` | 不要用 `<a href>` 或 token 拼 URL，否则绕过权限校验 |
