# 复用库：可复用方法与设计模式

> **写代码前先查这里，新建可复用项必须登记在这里。** 维护规则见 [AGENTS.md](../AGENTS.md) 的「复用库与防重复编码」一节。
> 目的：让后续开发（包括 AI 会话）知道项目里已有哪些方法、封装和模式可直接使用，避免重复编写。

## 0. 收录标准

- 同一逻辑已在 **≥2 处**使用，或预期会被多处使用（工具类、通用封装、公共组件）；
- 跨模块通用的**业务口径**（日期、权限、状态、进度、通知、周报）；
- 前端通用封装（请求、会话、路由守卫、样式 token、页面骨架）；
- 判断口诀：**下次写同类需求时，能不能直接引用现成的？** 能 → 必须登记。

## 5. 业务口径（模式级，不写代码也必须遵守）

- **实体层级**：项目 → 模块 → 工作项 → 任务；工作项另有**项目级工作项**（`module_id` 为空，承接跨模块测试/维护/缺陷修复/上线保障）；阶段性目标属于**项目**；模块只做功能划分，无阶段日期。
- **延期/临近**：`BusinessCalendar.nodeFlags` 是唯一口径；未开始/进行中且 `planEnd < today` → overdue；`0~3` 天内 → near。服务端实时计算，前端只展示。
- **功能交付**：工作项是最小交付单位，负责人确认完成；旧任务/资料/Bug不阻断、不推算进度。`ProgressRules.nodeProgress`仅DONE=100其余0；模块/项目由aggregate计算未取消工作项的已交付比例。阶段目标量化进度独立。
- **负责人双轨与继承**：模块负责人 → 模块工作项负责人 → 任务执行人；项目级工作项负责人由 PM/ADMIN 创建时指定、可为项目内任意有效成员；新建模块工作项默认继承模块负责人，新建任务默认继承工作项负责人；改派目标须为项目内有效且非 VIEWER 成员（`requireAssignable` 校验）。
- **通知触发（7 类）**：延期原因提交、标记受阻、工作项完成、任务指派（含缺陷分派）、周报发布、模块变更申请待审批（→PM）、变更审批结果（→申请人）。
- **周报**：未发布周实时计算；发布时写入 JSON 快照；按周一至周日归周。
- **工作项交付物**：一个工作项一份交付物清单（`node_deliverables`，`WANTED/PROVIDED`），清单项可选关联**同一工作项**的一个未删除附件；不参与工作项进度、不阻断工作项完成，只在工作项详情与时间线显示“已提供 x/y”。已完成/已取消工作项只能改状态。文件继续走 `attachments`（`owner_type='NODE'`），**不要**为交付物新增 `owner_type`，也不要把它做成“需要/产出”双向依赖。
- **权限矩阵**：`ADMIN` 全量；`VIEWER` 只读且不得写业务数据；`USER` 仅所属项目。项目内 PM > 模块负责人 > 工作项负责人 > 任务执行人。

## 6. 前端 · 请求与类型

| 名称 | 位置 | 用途 | 用法 | 注意 |
|---|---|---|---|---|
| `http` / `api<T>()` | `frontend/src/api/client.ts` | Axios 实例（baseURL `/api`、15s 超时）+ 统一请求封装 | `api<T>(method, url, data?, params?)` → 直接返回 `data`；`code!==0` 抛错；401 自动清会话并跳登录 | 视图里不要直接使用 axios/fetch；错误统一 `ElMessage.error((e as Error).message)` |

| `download()` | `frontend/src/api/client.ts` | blob 下载，Authorization 头由拦截器带上 | `await download(\`/attachments/${id}/content\`, 文件名)` | 不要用 `<a href>` 或 token 拼 URL，否则绕过权限校验 |
