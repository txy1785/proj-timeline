# 功能交付模型实施计划

2026-10-27 用户明确授权按“小功能交付＋资料＋Bug”更新功能。此决定覆盖旧任务完成率与默认四层操作流程。

## 产品与兼容口径

- 项目 → 功能模块 → 工作项；工作项是最小交付单位。阶段目标仍属于项目，模块无日期。项目级工作项保留。
- 工作项由负责人开始和确认完成，不以旧任务或资料数量推算进度、阻断完成。未开始/进行中不估算50%；DONE为100，其余为0。项目/模块进度表示未取消工作项的交付完成率，界面优先显示已交付x/y。
- 默认详情为功能说明、交付资料、Bug、活动记录。资料在一处显示交付要求与实际附件。默认不再创建通用子任务；已有非BUG任务、记录、工时、附件保留在“历史任务”入口，旧链接仍可读取。
- Bug 是独立问题记录，关联同项目原工作项。NOT_STARTED/IN_PROGRESS/DONE 工作项均可报告，CANCELLED不可新报；不再寻找进行中的项目级BUGFIX。功能交付后Bug仍可处理，不反复重开功能。
- 复用现有 tasks.kind=BUG、task_notes、TASK附件存储，保持id/记录/文件/通知深链，无清库或批量改写。历史分流Bug以同项目有效related_node_id为来源，否则以node_id为来源；不得跨项目追溯或扩大权限。服务端与前端共同使用来源工作项职务和Bug执行人权限，归档/VIEWER只读。
- Bug状态复用TODO/DOING/DONE，产品文案为待修复/修复中/已解决。同样提交expectedStatus，冲突刷新且保留草稿。Bug关联不能通过编辑悄悄改到别的功能或改类型逃避规则。
- 我的工作默认本人负责的工作项及本人待处理Bug；保留管理事项与历史任务访问。人员负载以有效项目工作项与Bug为主，旧人天字段/API保留历史兼容。已发布周报快照不改。

## 冻结接口

- `GET /workspace/deliveries` → WorkspaceDeliveryPage `{list,total,page,size,businessDate,timeZone,counts:{open,doing,overdue,done}}`。行NodeItem，含projectName/projectStatus。参数scope=OPEN|DONE|HISTORY（默认OPEN）、status=NodeStatus、ownerId（默认本人）、projectId、q、dueWeek、overdue（布尔）、page,size。OPEN有效项目未关闭项；DONE有效项目DONE；HISTORY含归档与取消；所有范围受可读项目限制。dueWeek筛选计划结束日所在自然周，overdue只选有效未关闭延期项。
- `GET /workspace/bugs` → WorkspaceTaskPage 同形。参数scope=OPEN|DONE|HISTORY、status=TaskStatus、assigneeId（默认本人）、projectId、q、overdue、page,size。仅kind=BUG；来源工作项有效项目且未取消，DONE来源仍可OPEN处理；HISTORY保留全部历史。nodeId是存储归属供抽屉加载；originNodeId/Name/Status/OwnerId/ModuleOwnerId是业务来源；nodeName按来源显示。
- `GET /nodes/{id}` 保留tasks，增加bugs（按来源收集）、bugCount、openBugCount、legacyTaskCount；Task BUG行返回originNodeId/Name/Status/OwnerId/ModuleOwnerId。跨项目或不存在的related不追溯，回退本工作项。前端从bugs展示问题，非BUG tasks仅历史入口。
- `POST /projects/{id}/bugs` 必须relatedNodeId，直接落该工作项，默认负责人继承功能负责人；原返回id/routedNodeId/Name兼容。bug-routing GET共享同一规则，无关联时canSubmit=false并提示选择功能，不写数据。
- `POST /nodes/{id}/status` 接受可选expectedStatus，在行锁下验证；无需旧任务全部完成。Bug写入沿用/tasks接口但根据BUG来源授权，来源DONE允许改状态和内容，来源CANCELLED禁止状态/内容修改；记录/附件沿用原权限，归档全部只读。
- `/workload` people新增 deliveryOpenCount/deliveryDoingCount/deliveryOverdueCount/deliveryWeekDueCount/openBugCount/overdueBugCount；有效项目与工作台对应scope/筛选一致，保留旧字段。
- ModuleItem新增totalWorkItems/doneWorkItems；Project.stats.total调整为未取消工作项数量，done为已交付，进度为交付完成率。原progress响应字段保留，详情不显示假百分比。

## 共享前端

- `/workspace/tasks?legacyOnly=true` 兼容历史任务专用SQL过滤，默认false保持旧接口；创建API kind=BUG统一报告规则，更新禁止普通任务转换BUG。
- TaskDrawer原有v-model/node-id/task-id/updated保持；自动识别BUG，展示Bug文案并允许来源DONE的合法动作。历史任务保留原说明/记录/附件，默认页面不再提供新建通用任务。
- BugReportDialog增加可选nodeId预选/锁定关联；项目入口显式选择，工作项入口直接预填。
- `taskWorkItemContext`、`canChangeTaskStatus`、`canEditTask`处理Bug来源；共享utils/bug.ts提供状态与动作。服务端仍最终授权。
