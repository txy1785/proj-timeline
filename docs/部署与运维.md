# 部署与运维

## 运行要求

- Java 17、Maven 3.8.6 或更高版本
- Node.js 20.19 或更高版本、npm（必须使用 `package-lock.json`）
- MySQL 8
- Nginx 1.24 或更高版本（容器部署已包含）

## 环境变量

复制根目录 `.env.example` 并设置数据库连接、至少 32 字节的 `JWT_SECRET`、业务时区和服务端口。生产环境不要使用示例密钥。后端启动时由 Flyway 自动执行迁移脚本（当前至 V9）。

文档上传相关变量：`UPLOAD_ROOT` 是本地存储根目录（默认 `./data/files`，容器内为 `/app/data/files`），`UPLOAD_MAX_BYTES` 是后端单文件字节上限（默认 52428800 = 50MB），`UPLOAD_MAX_FILE_SIZE` / `UPLOAD_MAX_REQUEST_SIZE` 是 Spring multipart 上限。Nginx 侧 `deploy/nginx.conf` 已设 `client_max_body_size 60m`，改上限时需同时调整这两处，否则会出现 413 或 4000 错误。`UPLOAD_ROOT` 必须纳入备份；容器部署已挂 `file-data` 卷。

## 首位管理员

仅在空库且不存在 ADMIN 时执行一次：

```powershell
$env:BOOTSTRAP_ADMIN_USERNAME='admin'
$env:BOOTSTRAP_ADMIN_PASSWORD='<强密码>'
$env:BOOTSTRAP_ADMIN_NAME='系统管理员'
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--app.bootstrap-admin=true"
```

控制台只记录用户名，不记录密码。创建成功后初始化进程自动退出；库中已有 ADMIN 时命令会失败。随后按普通方式启动，不要长期保留初始化参数。

## 本地构建与启动

```powershell
mvn -f backend/pom.xml test
mvn -f backend/pom.xml package
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend run build
java -jar backend/target/proj-timeline-backend-1.0.0.jar
```

前端生产目录是 `frontend/dist`。将其放入 Nginx 静态目录，并使用 `deploy/nginx.conf` 代理 `/api`。健康检查地址为 `/actuator/health`，OpenAPI 地址为 `/v3/api-docs`。

### 局域网访问（本机试用）

`frontend/vite.config.ts` 已固定 `server.host: true`（监听所有网卡，实际为双栈 `::`）和 `strictPort`，开发服务启动日志会打印 `Network: http://<本机IP>:5173/`。同一局域网的其他机器用该地址访问即可，不要再用 `--host 127.0.0.1` 或 `--host localhost` 启动，否则只有本机可达。

- **仅限可信内网试用**：开放到全网卡的是 Vite 开发服务器（会暴露前端源码与 HMR 通道），禁止暴露到公网，生产入口仍用 Nginx + `frontend/dist`。
- `/api` 与 `/actuator` 由 Vite 服务端代理到后端，局域网客户端只访问前端端口，后端端口不必对外开放；后端本身已监听全网卡。
- **代理端口口径**：代理默认目标是 `http://localhost:58080`（`API_PROXY_TARGET` 可覆盖，读的是操作系统环境变量，不读根目录 `.env`）。若后端以默认 `SERVER_PORT=8080` 启动，启动前端前需要 `$env:API_PROXY_TARGET='http://localhost:8080'`，否则页面能打开但所有接口 502。
- **选哪个 IP**：启动日志会列出所有网卡，虚拟机工具（VMware VMnet、Hyper-V）的地址不算；选实际在用的有线/无线网卡地址（本机为 WLAN 的 `192.168.0.18`）。
- **只支持 IP 与 localhost**：Vite 7 默认 `allowedHosts` 只放行 IP 字面量与 `localhost`，用主机名（如 `mypc.lan`）访问会返回 403 `Blocked request`，需要时在 `server.allowedHosts` 登记该主机名。
- **端口被占用时直接失败**：`strictPort` 使 5173 被占用时报 `Port 5173 is already in use`，先清理残留的 Vite 进程再启动（例如 `Get-NetTCPConnection -State Listen -LocalPort 5173` 查到 PID 后结束它）。
- 首次从别的机器访问若被拒绝，检查本机 Windows 防火墙：先用 `Get-NetConnectionProfile` 确认活动网络类别（本机 WLAN 为「专用」），再为实际运行的 `node.exe` 保留入站放行。管理员 PowerShell 按需执行：

  ```powershell
  New-NetFirewallRule -DisplayName "proj-timeline dev 5173" -Direction Inbound -Protocol TCP -LocalPort 5173 -Action Allow -Profile Any
  ```

- 上传大小上限、会话与权限不受影响；换网段或换机器后 IP 会变，以启动日志打印的 Network 地址为准。

接口变更后，在后端运行期间执行：

```powershell
npm --prefix frontend run api:types
```

生成的 `frontend/src/api/schema.d.ts` 应随代码提交。

## Docker Compose

设置 `.env` 中的 `DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`JWT_SECRET` 后执行：

```powershell
docker compose build
docker compose up -d
docker compose run --rm `
  -e BOOTSTRAP_ADMIN_USERNAME=admin `
  -e BOOTSTRAP_ADMIN_PASSWORD='<强密码>' `
  -e BOOTSTRAP_ADMIN_NAME='系统管理员' `
  backend --app.bootstrap-admin=true
```

管理员初始化命令会自动退出，常驻后端随后即可使用新账号登录。

## 演示数据

演示数据不属于 Flyway 迁移，只允许显式导入本地 `proj_timeline` 演示库：

```powershell
.\scripts\import-demo.ps1 -User root
```

需要密码时先临时设置 `MYSQL_PWD`，运行后立即清除。禁止对生产库执行 `docs/demo_seed.sql`。

## 备份、恢复与升级

升级前使用 `mysqldump --single-transaction` 备份数据库，并保存当前 jar、前端静态文件和环境变量。先在测试库执行新版本 Flyway 迁移和回归，再更新生产。恢复时停止写入，恢复数据库备份及对应版本应用；不要手工删除 `flyway_schema_history`。

上传文件单独存放于 `UPLOAD_ROOT`，不属于数据库备份范围：备份时同步归档该目录（容器部署对应 `file-data` 卷），恢复时与数据库恢复到同一时间点；只恢复数据库会留下指向缺失文件的附件记录。

如需回退 V4（文档附件），顺序是：先停服务、回退到 V3 的应用版本，再 `DROP TABLE attachments`，最后清理 `UPLOAD_ROOT` 下的文件。该操作会丢失附件元数据，执行前必须同时备份数据库与上传目录。V5 只修正 `owner_type` 的列注释，回退时单独忽略 V5 即可，不需要额外数据操作。

回退 V9（工作项交付物）：先停服务并回退到 V8 的应用版本，再 `DROP TABLE node_deliverables`。该操作会**丢失全部交付物清单数据**，执行前必须备份数据库。若期间已写入 `DELIVERABLE_ADD/UPDATE/DELETE` 日志，需先删除这些日志行、再把 `node_logs.action` 枚举改回 V8 的 16 个值，否则枚举变更会失败或截断数据。清单只关联既有的工作项级附件，不涉及磁盘文件，无需清理 `UPLOAD_ROOT`。

回退 V12（工作项模型）：先停服务并回退到 V11 的应用版本，再依次删除 `tasks` 的 `fk_tasks_related_node` 外键与 `idx_task_related_node`/`idx_task_kind` 索引、`tasks.related_node_id`、`tasks.kind`、`nodes.type`，最后把 `nodes.module_id` 改回 `NOT NULL`。**项目级工作项（module_id 为空）必须先迁移到某个模块或删除**，否则 NOT NULL 变更会失败；该操作会丢失工作项类型、任务类型与关联关系，执行前必须备份数据库。

日志输出到标准输出，由 systemd、Docker 或日志平台收集。JWT 仅含用户 ID，停用或改角色会在下一次请求即时生效；修改 `JWT_SECRET` 会使现有会话全部失效。
