# 部署与运维

## 运行要求

- Java 17、Maven 3.8.6 或更高版本
- Node.js 20.19 或更高版本、npm（必须使用 `package-lock.json`）
- MySQL 8
- Nginx 1.24 或更高版本（容器部署已包含）

## 环境变量

复制根目录 `.env.example` 并设置数据库连接、至少 32 字节的 `JWT_SECRET`、业务时区和服务端口。生产环境不要使用示例密钥。后端启动时由 Flyway 自动执行 `V1__baseline.sql`。

## 首位管理员

仅在空库且不存在 ADMIN 时执行一次：

```powershell
$env:BOOTSTRAP_ADMIN_USERNAME='admin'
$env:BOOTSTRAP_ADMIN_PASSWORD='<强密码>'
$env:BOOTSTRAP_ADMIN_NAME='系统管理员'
mvn -f backend/pom.xml spring-boot:run "-Dspring-boot.run.arguments=--app.bootstrap-admin=true"
```

控制台只记录用户名，不记录密码。创建成功后初始化进程自动退出；库中已有 ADMIN 时命令会失败。随后按普通方式启动，不要长期保留初始化参数。

## 本地构建与启动

```powershell
mvn -f backend/pom.xml test
mvn -f backend/pom.xml package
npm --prefix frontend ci
npm --prefix frontend run lint
npm --prefix frontend run typecheck
npm --prefix frontend run build
java -jar backend/target/proj-timeline-backend-1.0.0.jar
```

前端生产目录是 `frontend/dist`。将其放入 Nginx 静态目录，并使用 `deploy/nginx.conf` 代理 `/api`。健康检查地址为 `/actuator/health`，OpenAPI 地址为 `/v3/api-docs`。

接口变更后，在后端运行期间执行：

```powershell
npm --prefix frontend run api:types
```

生成的 `frontend/src/api/schema.d.ts` 应随代码提交。

## Docker Compose

设置 `.env` 中的 `DB_PASSWORD`、`MYSQL_ROOT_PASSWORD`、`JWT_SECRET` 后执行：

```powershell
docker compose build
docker compose up -d
docker compose run --rm `
  -e BOOTSTRAP_ADMIN_USERNAME=admin `
  -e BOOTSTRAP_ADMIN_PASSWORD='<强密码>' `
  -e BOOTSTRAP_ADMIN_NAME='系统管理员' `
  backend --app.bootstrap-admin=true
```

管理员初始化命令会自动退出，常驻后端随后即可使用新账号登录。

## 演示数据

演示数据不属于 Flyway 迁移，只允许显式导入本地 `proj_timeline` 演示库：

```powershell
.\scripts\import-demo.ps1 -User root
```

需要密码时先临时设置 `MYSQL_PWD`，运行后立即清除。禁止对生产库执行 `docs/demo_seed.sql`。

## 备份、恢复与升级

升级前使用 `mysqldump --single-transaction` 备份数据库，并保存当前 jar、前端静态文件和环境变量。先在测试库执行新版本 Flyway 迁移和回归，再更新生产。恢复时停止写入，恢复数据库备份及对应版本应用；不要手工删除 `flyway_schema_history`。

日志输出到标准输出，由 systemd、Docker 或日志平台收集。JWT 仅含用户 ID，停用或改角色会在下一次请求即时生效；修改 `JWT_SECRET` 会使现有会话全部失效。
