## 当前决定（本轮需求覆盖旧契约的对应限制）

1. 工作项仍为最小交付单元，执行状态保持 NOT_STARTED / IN_PROGRESS / DONE / CANCELLED。排期另按日期派生：开放项无计划完成日为待排期；无负责人显示待分配。标题是唯一必填业务字段，项目由当前上下文取得。项目开始日仍必填，模块仍没有日期。
2. 创建权限保持原边界：PM/ADMIN 可建项目级项；模块负责人可建其模块项。统一入口 PM 默认项目级、模块负责人默认其有权模块。允许清空负责人；未传 ownerId 保留原默认负责人兼容行为，显式 null 表示待分配。计划日期各自可空，两者均有时必须有序。未排期不算延期/临近，不伪造今天。开始工作需有效负责人，允许无承诺完成日。
3. 历史录入是显式模式：`historical=true`，初始状态 IN_PROGRESS 或 DONE，实际日期不晚于业务今天；DONE 必须实际完成日，实际开始日可未知；开始/完成都存在时有序。原计划未知保持 null。创建审计时间始终是记录时间。现有项可凭原因纠正实际日期，限 PM/ADMIN；不自动修改用户已录入的 134–139 等数据。周报按 actualEnd 归周，已发布快照不改。
4. 进度分母仍为未取消的已登记工作项，待排期计入分母，进行中不估算工作量；显示“已登记工作项 x/y 已交付”，不推断项目完成。空模块显示尚未拆分。待排期、待分配、空模块有独立数量提示。
5. PM/ADMIN 可填写原因把 DONE 恢复为 IN_PROGRESS；清除当前 actualEnd，保留 actualStart，完整记录原交付日期/状态与原因；使用 expectedStatus 防并发。正常交付后 Bug 仍独立处理。标题/说明可由原工作项管理者修改并留痕。状态后撤销入口走同样受控纠错，不能绕过权限。
6. 同项目移动工作项保持 ID、附件、记录、Bug 和历史。需有源项管理权限及目标模块管理权限；移到项目级限 PM/ADMIN。保留负责人，不暗中改派；跨项目拒绝。使用 expectedModuleId（null=项目级）和原因，锁定后复核。
7. 交付要求保留开工时基线；进行中新增/删除/改名/改派/改顺序必须理由，并用同事务审计保存变更前后完整快照（名称、负责人、状态、备注、关联、顺序）、操作者/时间。未开始自由维护；进行中状态/备注/附件沿原规则；DONE/CANCELLED 仍只可改状态，需结构变更先受控重开。历史版本从只追加的 node_logs 展示，不另建平行日志系统。
8. 通知默认跳过动作发起者，内容包括项目、工作项、操作者和动作；后台无操作者的系统通知保留。不要清除历史通知。
9. 草稿按账号+项目+新建/编辑ID隔离保存到 sessionStorage，明确恢复/放弃；关窗、Esc、切页、刷新保护。在途提交/上传不可关窗。保存并继续保留分组上下文并清空已提交内容。
10. 批量录入支持多行标题与历史录入预览；批量排期、负责人、移动、状态使用现有受控单项接口逐行执行，预览内容、逐行失败明细、仅重试失败行。列表单表头、可折叠模块，空组/完成组默认折叠，支持展开全部；保留筛选、分组和返回位置。
11. 项目文档复用已有 MarkdownEditor / MarkdownView 和附件版本体系：浏览器直接新建或编辑 Markdown，通过现有上传接口保存新版本，不要求用户手工生成文件。外部链接或仓库路径存为文档中的链接/文本，不由后端访问地址。标题点开预览，Markdown 安全渲染，原 HTML 仍关闭。上传入口一次直达。分类只展开有内容项，其余可展开。
12. 主导航为概览/工作/计划/资料，模块在工作中保留入口，周报/设置放更多；保留旧路由和任务独立详情页（用户此前明确选择独立页），不强制换回抽屉。计划页复用阶段目标编辑组件；设置旧目标入口可保留兼容入口，不复制表单。
13. 概览先显示下一步/需处理与近期交付，说明两行展开；统一深蓝 #2563EB、可辨焦点、零风险中性色；弹窗头尾固定正文滚动；移动导航收起，主要触控目标 44px。进展默认自动标题、输入即保存，格式工具按需，保留源码与下载能力。
