# 体验改善原型图册 v1

日期：2026-10-27 ｜ 类型：已批准的静态设计参考 ｜ 示例业务日期：2026-10-27

配套规格：[体验改善设计方案-v1](../../docs/体验改善设计方案-v1.md)。本目录为本轮新增设计，早期 `prototype/` 页面仍保留历史参考；用户后续已授权实施，运行界面位于 `frontend/src/`，验收见 [实施记录](../../docs/体验改善验收/README.md)。此图册保持为静态设计资产。图片展示关键状态，点击行为与条件详见配套文档。

## 建议先看三条路径

| 想判断的事 | 阅读顺序 | 重点 |
|---|---|---|
| 成员是否能直接开始干活 | P01 → P05 | 首页找到自己的任务，一次点击打开，开始/完成与写记录分开 |
| 负责人是否能安排并交付 | P02 → P03 → P04 → P05 | 统一建立工作项，继承负责人，拆任务，按完成条件收尾 |
| 项目是否可控 | P02 → P06 → P08 | 看具体风险、排期日期、阶段目标与周报；审批保持独立 |

P07 补充首次建立项目和提缺陷的有效/无接收位置状态。图中多个面板是分别发生的情景，不代表同屏同时打开多个弹窗。

## P01 我的工作

![P01 我的工作](images/01-my-work.png)

成员默认入口。四项本人待处理任务，直接开始/完成，点击名称打开 P05；所属工作项进入 P04。项目中的所有任务不会都被归成“我的任务”。普通成员没有新建任务与完成工作项按钮。

## P02 项目概览

![P02 项目概览](images/02-project-overview.png)

先交代项目交付内容、计划和责任，再呈现两项需处理风险与下一阶段目标。点击“查看并处理”进入 P04；“新建工作项”打开 P03。日期型阶段目标不因日期经过自动完成。

## P03 工作项与统一创建

![P03 工作项与统一创建](images/03-work-items-create-v2.png)

同一个入口建立模块工作项或项目级工作项，所能选择的位置取决于权限；选择模块后带入负责人。点击“创建并拆分任务”后创建工作项并进入 P04，不会静默批量生成任务。

## P04 工作项详情与风险处理

![P04 工作项详情与风险处理](images/04-work-item-detail.png)

任务、交付物、文件、变更记录按页签展开。风险原因可读、可由有权限者维护。任务未全部完成时说明剩余数量；交付物未齐全不作为完成门槛。

## P05 任务处理与快捷新建

![P05 任务处理与快捷新建](images/05-task-drawer-and-quick-create-v2.png)

左边是成员处理任务，右边是管理者新建任务的另一种状态。新建默认只展开名称、执行人和可选截止日，其他字段折叠。列表/看板/工作台共用任务详情；关闭后回到原位置。

## P06 清楚的交付排期

![P06 时间线](images/06-project-timeline-exact.png)

日期刻度、今日线、独立工作项行与阶段目标标记帮助判断何时交付。延期不会自动延长计划条；模块组头没有阶段日期，不增加依赖箭头和拖拽排期能力。

## P07 首次使用与提缺陷

![P07 首次使用与缺陷状态](images/07-first-project-and-bug-states-v2.png)

左边的下一步提示可以跳过，不要求先填完整套管理信息。右边展示缺陷提交与另一种无接收位置状态；已关联进行中的工作项仍可提交，不能一概禁用全部缺陷提交。

## P08 周报与模块审批

![P08 周报与模块审批](images/08-weekly-and-approval-v3.png)

周报突出完成、风险和下一步，历史工时折叠保留。右边审批只用于模块名称/描述/负责人变更，不给任务完成新增审批。PM/ADMIN 才能发布周报或审批。

## 评审时应确认

1. “我的工作 → 任务处理”是否符合成员每天的工作习惯。
2. “项目概览 → 新建工作项 → 拆任务”是否足够直接，模块分组和跨模块事项是否容易分清。
3. 风险原因、负责人、日期与处理动作是否在同一处能找到。
4. 新建任务折叠字段、项目固定导航和时间线信息密度是否合适。
5. 模块负责人直接编辑模块的现状冲突按配套文档第 5.1 节建议对齐；实现阶段已统一契约、界面和服务端，并通过负责人转交权限验证。

界面图使用内置 image_gen 制作并校对；P06 根据同一视觉规范从空白画布按日期精确绘制，避免生成图的条块比例偏差。全部交付为静态 PNG。[生成说明与完整提示词](生成说明与提示词.md) 保留提示词与选图说明，[设计校对记录](设计校对记录.md) 记录本轮验证。设计文档中的权限、流程、统计与错误状态说明优先于图片中的视觉细节。本轮尚未实施业务功能或完成业务回归。
